# Стандарт карточки zavod-red.ru («pro»-образ)

**Эталон:** `https://zavod-red.ru/analog/nord-9016-1-i22-71-4kvt`
Локальный образец: любой файл `analog/*.html` (семья на 100% в стандарте).

## Что считается «PRO» (8 обязательных признаков)

Проверяются по HTML-**элементам** (не по CSS-правилам) — см. `tools/card_audit.py`:

| # | Признак (ключ аудита) | Что это в разметке |
|---|---|---|
| 1 | `apro_nav`    | `<nav class="apro-nav">` — липкая табличная навигация карточки |
| 2 | `opis_first`  | секция `#opis` идёт **раньше** `#spec` (описание ведёт под hero) |
| 3 | `opis_lead`   | `<p class="opis-lead">` — 2–3 лид-абзаца описания с перелинковкой |
| 4 | `faq2`        | `<div class="faq2">` (2 колонки) внутри секции `#faq` |
| 5 | `seo_tbl`     | секция `#seo` + `<table class="seo-tbl">` соответствия исполнений |
| 6 | `why_grid`    | `<div class="why-grid">` — сетка преимуществ (4 карточки) |
| 7 | `gallery`     | `.p2-gal` (аналог) или `.p2-thumbs` (ZR-семьи) — миниатюры |
| 8 | `nav_faq`     | пункт «Вопросы» (`href="#faq"`) в apro-nav |

**Канонический порядок секций:** `opis → spec → dostavka → tehdoc → chertezh → faq → seo`
(у ZR-семей допускаются доп. секции `tz`, `analogi`, «похожие модели» — их не удаляем,
но `opis` всё равно ведёт, а `#seo` замыкает).

**Hero (единый для всех):** `p2` с `p2-h1`, ценой «Цена по запросу» + бейдж наличия,
`p2-offer`, строки `p2-rows`, две крупные CTA. Фото — по бренду (`br-{brand}`) у аналогов,
типовое ZR-фото у своих. Никогда не выдумывать цену.

Остальные семьи входят в основной `deploy-site-ssh.yml`.

## Рабочий цикл (аудит → фикс → проверка → деплой)

1. **Аудит:** `python3 tools/card_audit.py [семья] [--list-bad N] [--json]`
   Классифицирует каждую карточку: PRO / PARTIAL / THIN и печатает, каких признаков нет.
2. **Фикс** по семье — идемпотентными Python-трансформами (`tools/card_upgrade.py`),
   маркер уже-применённого фикса, чтобы повторный прогон был безопасен. Контент —
   шаблонно из параметров модели карточки (как в analog): без выдумывания цифр.
3. **Проверка:** повторный `card_audit.py семья` → должно стать `PRO N/N`.
   Плюс локальный рендер + `querySelectorAll` (элементы, не CSS) на 2–3 образцах.
4. **Деплой:** commit + push, `gh workflow run deploy-site-ssh.yml`
   (для `analog/` — `deploy-analog-ssh.yml` с `INCLUDE_ANALOG=1`). Проверить на боевом.

## Оркестрация субагентами

- **zavod-card-auditor** — прогоняет `card_audit.py --json` по scope, возвращает
  структурный отчёт (семья → уровни, недостающие признаки, примеры). Разведка, не правит.
- **zavod-card-fixer** — на одной семье: применяет трансформ, повторно аудитит, чинит
  до `PRO N/N`, рендерит образец. Правит файлы; отчитывается диффом-сводкой.

Большой парк (десятки тысяч файлов) чинится **шаблонным Python-трансформом**, а не
чтением каждого файла агентом; агенты оркестрируют по семьям и верифицируют выборкой.

## Подводные камни

- Аудит по подстрокам врёт: `.opis-lead` есть в CSS даже там, где нет в HTML. Всегда
  проверять `class="…opis-lead…"` как элемент (это и делает `card_audit.py`).
- `reduktor/index.html`, `*/index.html` — листинги, НЕ карточки: исключать из трансформов.
- `analog/` нельзя листить через `ls analog/*.html` (Argument list too long) — только glob.
- Порядок секций менять переносом целого `<section>…</section>`; проверять баланс тегов.
- Сброс кэша не нужен для HTML (no-cache), но при правке CSS/JS поднимать `?v=`.
- Тонкие семьи (ispolnenie/tiporazmer) — deep long-tail: приведение к pro = генерация
  шаблонного контента на каждую страницу. Согласовать объём перед массовым прогоном.
