# Кабинет ЗР — включение настоящих аккаунтов (слой 2) и CRM (слой 3)

Кабинет уже работает **без бэкенда**: регистрация создаёт лид в отделе продаж (через
`feedback.php`) и логинит клиента в кабинет на этом устройстве (localStorage). Ниже — как
включить настоящие аккаунты с паролем и входом с любого устройства.

> Секреты (пароль БД, токен CRM) хранятся ТОЛЬКО в `config.local.php` на сервере.
> Этот файл в `.gitignore` и не попадает в git/деплой. В репозитории — только образец.

## Шаг 1. Загрузить PHP на сервер
Файлы из папки `api/` (кроме `SETUP.md`) загрузите по FTP в `/public_html/api/`:
`config.php`, `db.php`, `register.php`, `login.php`, `logout.php`, `me.php`.
(`api/` намеренно исключён из автодеплоя в `deploy/build-dist.py`, поэтому заливается вручную —
рядом с уже работающим `feedback.php`.)

## Шаг 2. Создать базу MySQL
Панель Timeweb → **Базы данных MySQL** → создать базу и пользователя. Запишите имя базы,
пользователя, пароль. Хост обычно `localhost`. Таблица `users` создаётся автоматически при
первом запросе (см. `db.php`), отдельный импорт SQL не нужен.

## Шаг 3. Прописать доступы
На сервере скопируйте `api/config.local.sample.php` → `api/config.local.php` и впишите
доступы к БД. Поставьте `'DB_ENABLED' => true`. Готово — регистрация начнёт создавать
настоящие аккаунты. Фронтенд определит живой бэкенд автоматически (проверяет `register.php`,
кэш 1 час; ключ `zr_backend` в localStorage).

## Шаг 4 (необязательно). CRM
В `config.local.php`: `'CRM_ENABLED' => true`, `CRM_URL`, `CRM_TOKEN`. При регистрации
клиент дополнительно пробрасывается в CRM (server-side, best-effort).

## Безопасность (уже учтено в коде)
- Пароли — `password_hash`/bcrypt, никогда не хранятся и не логируются в открытом виде.
- Все запросы к БД — подготовленные выражения (PDO, без эмуляции) → нет SQL-инъекций.
- Сессия — httponly + Secure + SameSite=Lax cookie.
- CORS — только `https://zavod-red.ru`.
- Ответы на «нет пользователя» и «неверный пароль» одинаковы (не раскрываем наличие e-mail).
- Детали ошибок БД идут в `error_log`, наружу — общее сообщение.

## Проверка
```
curl -i https://zavod-red.ru/api/register.php            # ожидаем 405 (не 404) — файл на месте
curl -sX POST https://zavod-red.ru/api/register.php \
  -H 'Content-Type: application/json' \
  -d '{"name":"Тест","email":"t@t.ru","phone":"+79990000000","password":"secret1"}'
# ожидаем {"status":"success",...}, повтор — {"status":"exists"}
```
